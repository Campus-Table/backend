## 마일리지와 테스트 결제

신규 가입 잔액은 0P이며 가입 보너스를 지급하지 않습니다. 토스 테스트 결제창으로 충전합니다. `test_ck_` / `test_sk_` 결제창 API 키를 .env의 TOSS_CLIENT_KEY / TOSS_SECRET_KEY에 설정합니다. 결제위젯용 `test_gck_` / `test_gsk_` 키도 지원하며, 해당 키를 사용하면 결제 수단·약관 위젯을 표시합니다. 키는 같은 종류의 쌍을 사용합니다.

`/test-charge.html`에서 로그인 후 충전 금액을 입력하면 토스 카드 테스트 결제창이 열립니다. 승인 없이 적립하는 API는 없습니다. 프론트 앱에서도 아래 흐름을 동일하게 사용합니다.

1. 로그인 후 POST /api/mileage/charge/prepare `{ "amount": 10000 }`
2. 응답의 clientKey/customerKey/orderId/amount로 토스 SDK 결제창 호출
3. 성공 URL의 paymentKey/orderId/amount로 POST /api/mileage/charge/confirm
4. 승인 완료 응답의 balance를 화면에 표시

서버의 충전 기록에서 사용자·금액을 검증합니다. 동일 결제 재요청은 중복 적립 없이 최초 결과를 반환합니다. 기존 prepare 없이 confirm만 보내던 요청은 더 이상 허용하지 않습니다. 결제 승인 후 DB 장애가 나면 같은 orderId와 paymentKey로 재시도합니다. 외부 승인과 DB 사이의 영구 장애에 대한 별도 대사 작업은 여전히 필요합니다.

## 혼잡도와 식사 시간

혼잡도는 기존 30%/60%/85% 구간을 유지합니다. 식사 시간은 기존 설정을 유지하고 테스트 DB 구성 후 관리자 식당 설정 API로 변경합니다. 아래 시드의 새 테스트 식당만 기본값 30분을 사용합니다.

## 취소 및 환불

| 상황 | 환불 |
|---|---|
| 도착 인증 전, 만료 전 사용자 직접 취소 | 100% |
| 주문 후 1시간 미인증 자동 취소 | 100% |

날짜가 바뀌어도 주문 시각부터 1시간을 계산합니다. 예: 23:30 주문은 00:30에 만료되고 100% 환불합니다. 서버 중단으로 처리가 늦어져도 환불률은 100%입니다.

매분 만료 주문을 최대 100개 처리하며 조회 시점에도 동기화합니다. 정확히 1시간에 만료되고 자동 작업 반영은 다음 실행 시점까지 늦어질 수 있습니다. 같은 주문은 잠금 후 상태를 재확인해 한 번만 환불합니다. 도착 인증 후 사용자 취소는 허용하지 않습니다. 환불은 마일리지 반환이며 토스 원결제 취소가 아닙니다.

## 테스트 데이터

초기 데이터는 `src/main/resources/seed/seed.sql` 한 파일입니다. 식당 1개('학식당', 220석, 식사 30분, 09:00~20:00), 가게 9개, 메뉴 93개를 프론트 목 데이터(`mockData.js`) 기준으로 넣고, 가게 평균 대기시간은 3분, 이미지는 비워 둡니다(기본 이미지 표시). 같은 이름이 있으면 건너뛰므로 여러 번 실행해도 안전합니다.

- 수동 실행: `mysql ... campus_table < seed.sql` (테이블 생성 후).
- 기동 시 자동 입력: `SEED_ENABLED=true`이고 **식당이 하나도 없을 때만** 실행합니다(`SeedDataInitializer`). 기본값은 `false`입니다. 이미 식당이 있는 DB는 건드리지 않습니다.
- 사용자·마일리지는 넣지 않습니다. 관리자 계정은 `ADMIN_*` 환경변수로 `AdminInitializer`가 만듭니다.

## 인원 추정 외 CLOVA Studio 기능: 조건 기반 식사 추천

**회의록 문구:** “CLOVA Studio를 활용해 이미지 기반 식사 공간 인원 추정과 예산·메뉴 선호·대기시간을 반영한 식사 추천을 제공한다.”

추천의 목적은 사용자가 판매 중인 메뉴 중에서 선택할 수 있도록 돕는 것입니다. 예: '6천 원 이하, 한식, 빨리 먹고 싶어'라는 요청에 실제 등록된 메뉴 후보를 최대 3개 제시하고 가격·예상 대기시간·선정 이유를 설명합니다.

- 입력: 사용자 요청, 식당 ID, 선택 사항인 예산/선호 분류/대기시간 상한.
- 서버에서 실제 DB의 판매 중 메뉴를 조회하고 가격·예산으로 후보를 먼저 제한합니다. 메뉴 ID·가게 ID·이름·가격·분류·현재 예상 대기시간만 모델에 전달합니다.
- 출력: DB에 있는 메뉴 ID 최대 3개와 각 추천 이유. 후보가 없으면 추천을 비우고 조건 변경을 안내합니다.
- 모델은 메뉴·가격·대기시간을 만들어내지 않습니다. 서버가 응답 ID와 가격을 원본 후보와 대조하고, 판매 상태를 다시 확인합니다. 실패 시 일반 메뉴 목록을 표시합니다.
- 혼잡도는 안내에만 사용하며 추천이나 주문을 차단하지 않습니다. 예상 대기시간은 확정 시간이 아니라는 점을 표시합니다.
- 알레르기·영양 정보가 DB에 없으므로 알레르기 안전, 칼로리, 건강 효과를 추정하거나 보장하지 않습니다. 개인 신상이나 결제 정보는 보내지 않습니다.
- 메뉴 선택과 결제는 사용자가 수행합니다. 추천으로 자동 주문·차감하지 않습니다.
- 검증: 존재하지 않는 메뉴/품절 메뉴 추천 0건, 가격 조건 준수, 대기시간 근거 일치, 응답 실패 시 기본 목록 복귀.

이 문서는 기능 정의이며 추천 API 구현은 포함하지 않습니다. 현재 구현된 CLOVA 기능은 이미지 인원 추정입니다.
